# PRIVA-TRACE — Cryptographic Attribution and Immutable Decryption Provenance

## Smart India Hackathon 2026

Problem Statement:

> Cryptographic Attribution and Immutable Decryption Provenance for Multi-Recipient Encrypted Document Distribution.

---

## Project Overview

This project develops a secure multi-recipient encrypted document distribution system with:

- Post-Quantum Cryptography (PQC)
- ML-KEM / Kyber for key encapsulation
- ML-DSA / Dilithium for digital signatures
- AES-256-GCM for document encryption
- Quantum Key Distribution (QKD) integration abstraction
- Hybrid QKD + PQC key establishment
- Zero-Knowledge Proofs (ZKP) for privacy-preserving attribution
- Hardware Security Module (HSM) integration
- Cryptographically signed decryption records
- Immutable provenance ledger integration

## SIH26237 Integrated Backend and Desktop App

FastAPI backend (ML-KEM-768 + ML-DSA-65, ZKP attribution, signed hash-chain ledger, optional Hyperledger Fabric anchoring) with an Electron frontend.

### Prerequisites
- Python 3.11 and the native `liboqs` library (needed by `liboqs-python`)
- PostgreSQL with a database named `sih26237`
- Node.js 18+ (for the frontend)
- Optional: Hyperledger Fabric test network in WSL (see `fabric/README.md`)

### Backend
```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
.\run_dev.ps1
```
`run_dev.ps1` creates a local `.jwt_secret` on first run and asks for the Postgres password. The API runs on http://127.0.0.1:8001.

### Frontend
```powershell
cd frontend
npm install
npm run dev
```
The app should open on http://localhost:5173. If that port is busy, close the old window, otherwise CORS will block API calls.

### Environment variables
| Variable | Purpose |
|---|---|
| `DATABASE_URL` | Postgres URL (built by `run_dev.ps1` if unset) |
| `JWT_SECRET_KEY` | Token signing key (generated by `run_dev.ps1`) |
| `CORS_ORIGINS` | Comma-separated allowed origins, e.g. `http://localhost:5173` |
| `QKD_MODE` | `off` (default), `simulated`, or `hardware` |
| `FABRIC_ENABLED` | `1` to enable Fabric anchoring |
| `FABRIC_NETWORK_DIR`, `FABRIC_CFG_PATH`, `FABRIC_BIN_DIR`, `FABRIC_WSL_DISTRO`, `FABRIC_CHANNEL`, `FABRIC_CHAINCODE` | Fabric network settings (WSL paths) |

### Smoke test
With the backend running:
```powershell
python smoke_test.py --user demo --password "<12+ char password>" --fabric
```
(`--fabric` only if the Fabric network is up.)

### Known limitations
- QKD is simulated (random keys, no hardware).
- Traffic is plain HTTP; TLS-PSK needs Python 3.13+.
- The watermark CNN weights (`ml/`) are not in this repo.
- Fabric runs against a local test network.
